# 启萃声量中台 MVP

内部使用的评论执行、舆情监测与本竞品分析看板。

## 已实现

- 三条评论主线的条数、目标和费用进度
- 按笔记 ID / 链接抓取全部主评论与全部楼中楼
- 按关键词和近 90 天时间范围扫描本品、UGC 与竞品笔记
- 导入 `启萃｜26年.xlsx`，识别自有笔记并与扫描结果去重
- 导入供应商评论交付表，复核原文一致、有修改和未外显状态
- 评论正向、负向、问询、品牌与竞品提及分类
- 关键评论处置台：需达人回复、需删除、处理方式和处理率
- 每次抓取保存指标快照，仅保留关键评论，并追踪评论消失与回复变化
- D1 持久化、R2 文件绑定与内部身份信息接入

## 本地启动

项目会复用上一级目录的 `config.json`，不会把凭证复制到源码中。

### 1. 普通开发启动（默认 Node Runtime + 主库）
```bash
cd feihe-mvp
node scripts/dev.mjs
```
- 本地启动默认在 Node Runtime 下运行，直连主库 `data/local.db`。
- 本机环回访问（`http://127.0.0.1:5173/`）自动注入受限本地开发身份（`user-editor` 业务编辑者），无需配置测试头或环境变量。

### 2. 显式 Cloudflare Runtime 模式（保留选项）
```bash
ENABLE_CLOUDFLARE_RUNTIME=true node scripts/dev.mjs
```

### 3. 生产部署与鉴权
- 生产环境（`REQUIRE_PROD_AUTH=true` 或 `NODE_ENV=production`）严格强制公司网关签名鉴权，禁用本地开发身份注入。
- 使用 `npm run build` 打包 Cloudflare Workers 生产部署产物。

## 推荐使用顺序

1. 在“笔记资产”导入自有笔记 Excel。
2. 输入本品与竞品关键词，扫描近 90 天笔记。
3. 对需要监测的笔记运行全量评论抓取。
4. 在“舆情处置”更新达人回复、删除等处理状态。
5. 在“供应商核验”导入交付表并运行隔天外显复核。

生产环境所需变量见 `.env.example`，敏感项应配置为站点密钥。
