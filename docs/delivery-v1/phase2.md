## 1. 执行范围与拥有边界确认

本批次严格遵循以下边界与原则：
- **独占代码集**：
  - `lib/business-sync/store.ts`：同步任务规格、版本冲突校验、租约锁机制、按日期补跑与状态聚合。
  - `scripts/automation-read-bridge.py`：对 `automation` 各平台只读取数的受控隔离桥接，向子进程传入非敏感账号与任务标识，绝不透传或输出 Cookie、Secret、Token。

  - `scripts/business-scheduler.py`：基于 APScheduler 的独立后台调度进程，与前端解耦，前端窗口关闭仍持续执行。
  - `scripts/configure-business-sync.mjs`：项目任务配置与版本同步工具。
  - `app/api/business-sync/route.ts` 与 `features/data/BusinessSyncPanel.tsx`：状态查看、排队执行、暂停/恢复、按日期补跑面板。

  - 未调用任何旧写飞书执行器，不直接回写线上真实飞书多维表。

## 3. 核心机制落地

1. **凭据非敏感化**：
   - 前端与任务配置仅传递 `{ platform, accountId, entityIds }` 等非敏感代号。
   - 错误与日志均经过敏感信息脱敏（去除任何 Cookie/Authorization/Token 痕迹，截断长 URL）。
2. **归因回刷与按日期补跑**：
   - 任务规范支持 `refreshDays` 与 `attributionDelayDays`，按平台特性计算生效窗口。
   - 支持管理端发起特定区间（`window_from`, `window_to`）的补跑，幂等写入且不导致业务截至日期回退。
3. **独立后台与进程守护**：
   - 调度进程 `scripts/business-scheduler.py` 独立运行，即使前端 UI 页面关闭，后台作业仍受控按周期唤醒。
   - 租约超时自愈机制：如 worker 意外崩溃，过期租约自动释放并将未完结任务置为 `interrupted`。
4. **竞品模块对接准备**：
   - 同步类型扩展支持 `competitor_ipscg`，已在规格中预留参数校验（任务 ID、关键词、页预算、限速），待竞品执行器就绪后可直接挂载。
