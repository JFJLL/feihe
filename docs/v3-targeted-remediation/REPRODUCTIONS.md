# 问题复现

## 起始版本与前两个失败用例

起始工作区 clean，分支 codex/platform-upgrade-v3，HEAD 精确为 78f56d8b6d9d02d4d66ddb97b11f1ebd30b47787。先创建独立返修分支，再写反例，随后修复。

### 记录计数为 0

1. 通过本地数据接口写入三条普通任务，字段包含 task、amount，没有 custom 字段。
2. 打开通用看板，选择任务数据 A，进入自定义，添加指标卡，选择记录计数。
3. 卡配置为 metric=custom、aggregation=count、field 为空。
4. 起始引擎与实时预览得到 0；正确值为 3。

首次单元脚本中真实引擎与指标 API 均出现 0 != 3。首次浏览器用例操作 DOM 后对预览数字执行相同断言，失败并生成 trace 和截图。
证据：[初始单元失败](initial-unit-failures.txt)、[初始浏览器结果](initial-browser-results/)。
保留相同计数断言，最终通过；用户 Chrome 再次通过页面新建、发布、刷新，得到 3。

### 409 后保存并切换丢草稿

1. 建立真实数据集 A/B 与已发布看板。
2. 在页面编辑卡片标题形成草稿。
3. 经真实看板接口发布另一版，使当前页面版本过期。
4. 页面选择 B，点击“保存修改”。
5. 服务端真实返回 409。起始页面仍切换 B，重新加载后覆盖 draftCards。

初始浏览器断言“仍在 A”失败，实际下拉为 B；草稿保护失败。trace 和 error-context 均保留。
最终用例把服务端真实推进四个版本，防止 localVersion+1 猜测通过；核对 409 响应、冲突弹窗真实版本、A、草稿、编辑态和服务端已有数据。
另有 500 与 internetdisconnected 故障用例：错误时保存 A 与草稿，移除故障后真实保存成功才切换 B。

## 返修过程中新增发现

### 选择器覆盖下一控件

真实 B 路径选择完自定义选择器后，嵌套 label 的默认点击行为重新打开选择器，覆盖下一输入。保留对应失败 trace，选项点击阻止 label 的默认行为并停止冒泡，原输入操作通过。

### 浏览器后退提前卸载草稿

真实浏览器 history.back() 先被路由运行时恢复页面，popstate 拦截发生过晚。Chrome 的 Navigation API 在可取消 traverse 时提前拦截，保留当前页面及草稿，并打开未保存确认。保留传统 beforeunload 与 popstate 兼容处理。最终浏览器用例验证模块跳转、项目切换、浏览器后退。

### 用户 Chrome 中 390px 弹窗布局

实际截图发现弹窗位于左上，内外两层滚动条。证据：[修复前](manual-chrome-initial-layout.png)。
统一 Dialog 设置自动居中、外层隐藏溢出、内层扣除边框高度，并锁定背景滚动。
移动端用例增加居中及外层纵向不溢出断言，卡片、映射、未保存、冲突与确认弹窗均通过。
[修复后](manual-chrome-390-dialog.png) 显示记录数 3、唯一内容滚动区和可见操作区。

### ISO 小数秒被改成非法日期

输入 2026-10-01T12:00:00.123+08:00，旧共享转换把所有点替换成横线，输出 2026-10-01T12:00:00-123+08:00。
先新增反例并确认失败：[失败日志](date-mapping-red.txt)。
替换限定在日历日期开头，保留 ISO 小数秒与时区；同时保留 2026/10/01 -> 2026-10-01 转换。最终反例通过。

## 测试环境问题

早期外部 fetch mock 没有进入 RSC 运行上下文，测试身份向实际飞书认证端点使用虚构凭据收到 400。随后改为独立的本地飞书 HTTP 模拟服务器，测试构建限定替换 vendor origin。没有完成真实飞书业务同步，没有写入生产数据。

单元/API 与浏览器进程曾共用 Vite 优化缓存，导致动态模块无法加载。改为 node_modules/.vite 下四个独立缓存目录，避免浏览器运行中被其他检查替换。有关失败保留在中间迭代目录。

旧图表静态渲染测试的 VM 缺少 URLSearchParams。保留原断言，给测试 VM 补齐标准全局；原失败日志为 [historical-regression-initial-failure.txt](historical-regression-initial-failure.txt)，最终七段回归命令通过。
